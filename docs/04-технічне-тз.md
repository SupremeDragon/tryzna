# 04 — Технічне ТЗ

## 1. Рушій: Godot 4.7 `[v1]`

**Обґрунтування вибору:**

- Ти вже маєш два робочі проєкти на Godot 4.7 (`F:\SMDArena`, `F:\er-on`) — нуль часу
  на вивчення інструмента.
- 2D в Godot — найкраще на ринку: вбудований Y-sort, `Light2D` з нормал-мапами,
  `CanvasModulate`, шейдери на `CanvasItem`, `Parallax2D`, `TileMapLayer`.
- Безкоштовний, MIT, **нуль роялті** — при релізі в Steam це десятки тисяч доларів
  різниці проти Unity.
- GDScript — швидка ітерація. Я можу писати й правити код прямо тут, без збірки.
- Малий білд (~70–120 МБ), експорт у Steam працює з коробки.

**Відкинуті варіанти:**
Unity (важчий, гірше 2D-світло, історія з ліцензіями) ·
GameMaker (нормальний, але слабший для стратегічного шару Акту III) ·
RPG Maker (упреться в стелю на першій же нестандартній механіці) ·
власний рушій (самогубство).

**Налаштування проєкту:**

| Параметр | Значення |
|---|---|
| Рендерер | `Forward+` (Vulkan). Фолбек `Mobile`, якщо будуть скарги на старе залізо |
| Базова роздільність | `1920 × 1080` |
| Stretch mode | `canvas_items` |
| Stretch aspect | `expand` |
| Мова | GDScript (типізований, статичні типи **обовʼязково**) |
| Warnings | **як помилки** (як в `er-on`) |
| Фізика | 60 Гц фіксована |

**Правило №1 архітектури:** `core/` **нічого не знає про `scenes/` і про UI**.
Це той самий урок, який уже спрацював у `SMDArena` — симуляція окремо, подання окремо.
Завдяки цьому бій можна ганяти в тестах без відкриття гри.

**Правило №2:** системи спілкуються через `EventBus` сигналами, а не прямими
викликами. Інакше на 20-й годині розробки все злипнеться в один клубок.

## 3. WorldMode — центральна абстракція `[v1]`

Увесь світ живе в логічних координатах `Vector3(x, глибина, висота)`, а на екран їх
переводить `Projector` двома множниками:

```gdscript
# core/space/projector.gd
func project(p: Vector3) -> Vector2:
	return Vector2(p.x, p.y * depth_scale - p.z * height_scale)
```

І це **вся** «псевдо-3D» система гри. Обидва переходи — анімація одного з двох чисел
до нуля:

| Світ | `depth_scale` | `height_scale` | Час унизу |
|---|---|---|---|
| `VYS` | 0.92 | **0.00** | стоїть |
| `PLYN` | 0.55 | 1.00 | тече |
| `NYTS` | **0.00** | 1.00 | тече |

```gdscript
# autoload/world_mode.gd
func fold_to(mode: Mode, duration: float, hold: float = 0.0) -> void
```

`hold` — пауза перед рухом камери. Використовується тільки для піднесення: час
спиняється одразу, а камера рушає через 0.75 с. Ця затримана мить і продає перехід.

Глибина твіниться `EASE_OUT` (спершу підіймаєшся й бачиш більше), висота —
`EASE_IN` + `TRANS_QUINT` (вежі осідають пізно й різко, окремим ударом).

Гравець — **один** `Actor` з підключеним `MovementSolver`. Не три різні контролери.
Це критично: інакше кожна нова механіка доведеться писати тричі.

| Режим | MovementSolver | Особливості |
|---|---|---|
| `PLYN` | `TopDownSolver` | 8 напрямків, інерція, `y_sort_enabled = true` |
| `VYS` | `TopDownSolver` (той самий!) | інші константи: швидкість, без інерції, більший зум |
| `NYTS` | `SideSolver` | вісь X + гравітація + стрибок, `y_sort_enabled = false` |

Тобто **реально нових розвʼязувачів усього два**. Висі — це Плинь з іншими цифрами
й іншою камерою. Величезна економія.

## 4. Формати даних `[v1]`

**Предмети, навички, NPC** → Godot `Resource` (`.tres`).
Редагуються в інспекторі Godot, типізовані, не ламаються мовчки.

**Квести, діалоги, Спогади** → JSON.
Причина: їх буде багато, їх писатимеш переважно ти (текст), і JSON зручно правити в
будь-якому редакторі, не відкриваючи Godot.

Приклад діалогу:

```json
{
  "id": "gomin_first_meeting",
  "speaker": "litopysets",
  "nodes": [
    { "id": "n0", "text": "Ти дивишся на мене так, ніби вже знав мене колись.",
      "next": "n1" },
    { "id": "n1", "text": "Я знала.", "choices": [
        { "text": "Я з Ладу.",        "next": "n2", "ledger": "reveal_truth" },
        { "text": "Тобі здалося.",    "next": "n3" },
        { "text": "[Мовчати]",        "next": "n3", "requires": "skill.pamyat>=2" }
    ]}
  ]
}
```

**Локалізація** — CSV із першого дня, навіть якщо мова поки одна. Українська —
основна, англійська — при релізі. Додати локалізацію потім у 10 разів дорожче, ніж
закласти зараз.

## 4-bis. Наслідок канону Висей: `Ledger` не може лишитися автолоадом

Зараз `Ledger` — глобальний синглтон на одного гравця. За каноном Акту III
(див. [07-висі-геймплей.md](07-висі-геймплей.md)) **реєстр діянь потрібен кожній
названій людині**: бог читає чужу сторінку, перш ніж відповісти на молитву.

Це дешево перепланувати зараз і дорого переробляти через рік. План:

```gdscript
# core/soul/deed_ledger.gd
class_name DeedLedger extends Resource
    var deeds: Array[Dictionary]
    var prayer_trail: Array[Dictionary]   # коли й про що молився

# autoload/ledger.gd лишається, але стає ТОНКОЮ обгорткою
# над DeedLedger головного героя.
```

Тобто: логіка переїжджає в `DeedLedger`, автолоад тримає екземпляр гравця й
делегує. Для Акту I нічого не змінюється, для Акту III усе вже готове.
**Робимо це до M2**, поки Реєстром користуються два виклики.

## 4-ter. Делегування як камера — уже підтримано архітектурою

Канон Акту III (див. [07-висі-геймплей.md](07-висі-геймплей.md), §3): сутність не
ходить, а посилає слуг, і може дивитися їхніми очима.

Технічно доручення слузі — це рівно `«завантаж локацію X у режимі світу Y»`.
Тобто **та сама операція, яку ми вже написали в M1**: `WorldMode.set_mode()` +
`_load_world()` + `Projector`. Три окремі світи з окремими локаціями вже працюють.

Отже для Акту III треба буде додати не рушій, а **дані**: список доручень, куди
й у якому режимі вони ведуть, і хто їх виконує. Ніякої нової системи камер,
проєкцій чи рендеру.

**Наслідок для M2:** коли робитимемо завантаження локацій «по-дорослому» (не
процедурний сірий бокс, а сцени з диска), одразу закладаємо, що **точка входу в
локацію приймає режим світу як параметр**, а не бере його з глобального стану.

## 5. Правила коду `[v1]`

- Типізований GDScript **завжди**: `var hp: int = 10`, `func hit(dmg: int) -> void:`.
- Warnings = errors у налаштуваннях проєкту.
- Імена: файли й папки — `snake_case`; класи — `PascalCase`; сигнали — минулий час
  (`quest_completed`), не `on_quest_complete`.
- Українською пишемо: коментарі, тексти, документацію. Англійською: імена змінних,
  функцій, файлів. Змішувати всередині одного рядка — ні.
- Кожен новий `core/`-модуль отримує мінімальний тест-сценарій у `tests/`.
- Git з першого коміту. `.gitignore` під Godot 4. Комітимо після кожної робочої фічі,
  не «раз на тиждень усе разом».
