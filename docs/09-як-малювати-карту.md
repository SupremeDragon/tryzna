# 09 — Як малювати карту

> Для Міші. Нічого малювати від руки не треба: усі плитки вже намальовані,
> ти їх тільки **розставляєш**. Це ближче до укладання плитки в кімнаті, ніж
> до малювання.

## Куди тицяти

1. У Godot відкрий **`scenes/plyn_map.tscn`** (панель «Файлова система» ліворуч
   унизу → тека `scenes` → подвійний клац на `plyn_map.tscn`).
2. У дереві сцени (панель «Сцена» ліворуч угорі) обери шар:
   - **«Земля»** — те, по чому ходять: трава, ґрунт, камінь, вода, пісок;
   - **«Предмети»** — те, що на ній стоїть: дерева, паркани, хати.
3. Щойно обраний шар — унизу зʼявляється вкладка **«TileMap»**. Там палітра
   плиток.
4. Тицяєш плитку в палітрі → клацаєш по полю. Тягнеш мишею — кладеться доріжка.

**Гарячі клавіші там же:** `D` — піпетка (взяти плитку, на яку вказуєш),
правий клац — стерти.

## Чому шарів два, а не один

«Предмети» мають увімкнене **сортування по Y**. Через це дерево, яке ближче до
глядача, само лягає поверх того, що далі. Якщо покласти дерево на шар «Земля»,
воно почне ховатися за сусідніми клітинками — це не помилка редактора, це
означає «ти поклав його не на той шар».

## Що де в наборі

Атлас — `art/plyn/atlas_terrain.png`, сітка **12 на 11**, 121 плитка від Міші
плюс шість зроблених із них парканів-накладок. Повний перелік з іменами
вихідних файлів лежить поруч: `atlas_terrain-склад.txt`.

вгадувати — і вгадує погано.

## Про паркан окремо

Усі шість готових парканів набору намальовані однаково: кубик землі, а на ньому
паркан **одразу по двох передніх ребрах ромба**, кутом. Однією такою плиткою
двір не обвести — у ряд вони лягають то внапуск, то з дірками, і на екрані це
читається як розкидані стовпчики, а не як огорожа.

Тому з них зроблені **накладки**: сам паркан, без власної землі, розтягнутий
рівно на ребро ромба й розрізаний навпіл. З половинок складається замкнений
периметр будь-якого розміру, а під ним видно будь-яку землю — хоч траву, хоч
витоптану стежку.

Двір огороджується так: ближні до глядача два боки малюються **на самому
дворі**, дальні два — **на сусідніх клітинках за ним**. Межа завжди належить
тій клітинці, для якої вона передня.

## Якщо плитки лягають криво

Числа сітки задані в `game/tools/build_tileset.gd`:

- `DIAMOND` — розмір самого **ромба** (173 на 128). Не розмір картинки.
  Тут була пастка: ромб у цьому наборі **НЕ 2:1**, він вищий. Поки я задавав
  його «як заведено», плитки не сходилися й між ними зяяли щілини.
- `LIFT` — на скільки картинка піднята над клітинкою (28). Менше — плитки
  тонуть у землю, більше — висять над нею.

Після зміни треба перезібрати набір:

```
Godot --headless --path game --script res://tools/build_tileset.gd
```

## Звідки взявся атлас

Плитки лежать поштучно в `art_src/cut/`. Атлас із них збирається у два кроки:

```
python tools/pack_cut.py art_src/cut game/art/plyn/atlas_terrain.png --cols 12
python tools/make_fence_overlays.py
```

Другий крок обовʼязковий і йде саме після першого: він домальовує в порожні
клітинки атласу паркани-накладки, а `pack_cut.py` затирає атлас цілком.

Плитки вирівнюються по НИЗУ, а не по центру: кубик землі й дерево різної
висоти, і якби їх центрувати, дерево злетіло б над землею.

**Якщо десь лишилося синьо-сіре тло** — підніми поріг: `--tolerance 66` і вище.
Дірки всередині плиток при цьому не постраждають: вони заливаються назад за
звʼязністю (справжнє тло дотикається краю картинки, а пляма в камені — ні).

**Godot не побачить нових пікселів сам.** Атлас переписаний ззовні, а рушій
тримає свою імпортовану копію, тож після зміни атласу треба один раз пройтися
редактором, інакше нові плитки малюються порожнечею:

```
Godot --headless --path game --editor --quit
Godot --headless --path game --script res://tools/build_tileset.gd
```

Стара дорога — нарізка цілого аркуша (`tools/build_atlas.py` разом із
`tools/grid_probe.py`) — лишається на випадок, якщо колись прийде аркуш із
рівною сіткою. Для згенерованих аркушів вона працює погано: крок у них дробовий
і різний по осях, і на чотирнадцятому стовпці плитки вже ріжуться навпіл.

## Село, яке малює код

`game/tools/paint_balka.gd` малює Тиху Балку сам і кладе її в
`scenes/balka.tscn` — окремо від твоєї карти в `scenes/plyn_map.tscn`, її ніщо
не чіпає.

```
Godot --headless --path game --script res://tools/paint_balka.gd
Godot --headless --path game --script res://tests/check_map.gd
```

Садиби там не розставлені руками: код перебирає місця по сітці від перехрестя
назовні й ставить двір там, де той **влізає цілим** — з парканом, хвірткою в
бік дороги та стежкою від дверей до дороги. Тому село густішає біля майдану й
рідшає до узлісся само собою.

`check_map.gd` не дивиться на карту очима, а рахує: скільки предметів у воді,
скільки парканів на дорозі, скільки дахів висить без стіни. Усі три числа мають
бути нулями.
